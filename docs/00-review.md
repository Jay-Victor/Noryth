## 0. 前提假设（可调整的默认值，不是问卷）

方案里有四处没有被明确，但会**翻转架构**。以下是我替你锁定的默认值；不同意任何一条，改这里即可，后续设计按新值重推。

| # | 前提 | 默认取值 | 若改成另一种，哪些结论会变 |
|---|---|---|---|
| A1 | 部署形态 | **单机桌面**，一个用户、一个项目一个文件夹、离线可用（仅在调用模型时需要网络） | 若要做多人协作/云端，`cognition`、`lock`、`branch` 全部要加租户维度，回退语义也要重写 |
| A2 | 规模 | 单项目 ≤ 60 万字、≤ 300 个场景、≤ 400 个角色实体、≤ 20 万记忆节点 | 超过 50 万节点，暴力向量扫描（55 ms@12 万）才需要在 P2 引入 sqlite-vec |
| A3 | 写入侧的模型权限 | **模型只产出提案，命令层校验后提交**；模型不持有文件写入、数据库修改、越界检索权限 | 若让 Agent 直接写库，"知识边界"和"设定锁"就退化成提示词约束，等于没有 |
| A4 | 人格/角色卡算不算"记忆" | **不算**。角色卡、世界观、价值观进 config + 版本化 + 人工审批；记忆是可错的，人格不是 | 若把人格当记忆节点，一次错误抽取就能改写角色，且会被检索召回放大 |

还有一个**不由我决定**的量：模型供应商与价格。成本模型里的 2 元 / 8 元每百万 token 是占位符，请在设置页填真实值。

## 1. 需求条目化与判定

判定的含义：**保留**=照做；**修改**=目标不变但机制要换；**删除**=这一条不该存在；**补充**=原方案缺的，且缺失代价高于实现成本。

### 1.1 项目与界面

| ID | 需求 | 判定 | 说明与失效机制 |
|---|---|---|---|
| R1 | 首页创建项目，绑定一个文件夹作为工作区 | 保留 | — |
| R2 | 正式创作页为多分区工作台（左导航 / 会话列表 / 对话 / 文本 / 文件列表） | **修改** | 五栏在 1440 px 下会把对话区压到 420 px，低于可读宽度。改为**按宽度自适应**：1440 四区（正文以标签切换）、1600 起五区并列（剧场 + 正文预览同屏）、<1200 侧栏变抽屉。见 `04-ui.md §3` |
| R3 | 首页与创作页分离 | 保留 | 首页是项目选择器，不承载任何创作状态 |
| R4 | 设置：skill 管理、主题、模型提供商、agent 配置、关于 | 保留 | 补一条：**密钥只进 OS 凭据库**，不进项目文件夹、不进 Git、不进导出包 |
| R5 | CLI → TUI → Electron GUI | **修改** | 顺序保留，但 CLI 不是"过渡产物"：它是**唯一的无头测试面**，P0–P3 的全部验收都跑在 CLI 上。GUI 不允许成为唯一入口 |

### 1.2 多 Agent 剧场

| ID | 需求 | 判定 | 说明与失效机制 |
|---|---|---|---|
| R6 | 用户可创建多个角色 Agent + 旁白 Agent | 保留 | 角色 Agent 必须绑定 `entity`，不是自由文本人设 |
| R7 | Agent 在群组中对话，自动推进情节 | **修改** | "自动推进"不能靠 Agent 自发。推进是**导演（代码）**的职责，角色只有欲望。见 R9 |
| R8 | 用户可扮演其中一个角色或旁白 | 保留 | 需要一个显式的 `WAITING_FOR_HUMAN` 状态，不能在循环里 sleep 等人 |
| R9 | 发言权调度：自动判断 + 用户指定 | **修改为代码评分** | 见"最贵的错误 #1"：无调度时单人连任 12–15 拍、占 52–58%、旁白 0%。而且每拍让模型选人 = 每场多 40 次调用 / +50,400 tok，且回退后无法复演 |
| R10 | 角色只拿到"它该知道的" | **修改为前置过滤** | 不能"先全量喂进去再要求它别说"。实测全量注入时每次装配 **128.7 条越权事实**；前置过滤后为 0 |
| R11 | 旁白负责环境/动作/心理/背景/推进 | **修改** | 旁白只写**句子**。旁白默认**零感知**（`audience=[]`），不能因为"职责是推进"就获得发明事实的权限 |
| R12 | 场景目标 + 冲突 + 事件卡 + 结束条件驱动 | 保留 | 结束条件必须机器可判定（六算子），"他们终于和解了"这种写法等于没有条件 |
| R13 | 用户可随时插手指定发言 / 暂停 / 收束 | 补充 | 硬指定必须**同时豁免阻尼与硬上限**，否则用户点了谁、系统还是不给谁说话 |

### 1.3 记忆与一致性

| ID | 需求 | 判定 | 说明与失效机制 |
|---|---|---|---|
| R14 | 三层记忆：长期/场景/短期 | 保留 | 但三层不是三个库，是**三种检索 scope + 三种预算**。见 `03-agents.md §6` |
| R15 | 向量数据库 + 结构化状态库 | **删除"向量数据库"这一层** | 小说项目 12 万条 512 维向量，Node 暴力扫描 **55 ms**（测见 bench_vector.mjs）。独立向量库带来的是进程、端口、备份不一致，换不来延迟 |
| R16 | 短期记忆按身份选择性载入最近 N 轮 | **修改** | N 不该是常数，是 token 预算 + 降级阶梯（full→summary→triple→id→drop）。固定 N 轮在东语种混排下会溢出或浪费 |
| R17 | 关键事实库：身份/时间/地点/物品/秘密 | 保留 | 补：**事实有真假三态**（真/未知/假）。谎言是小说核心机制，一句台词不能覆盖客观状态 |
| R18 | 冲突检测：说了不该知道的事 / 关系突变 / 时间线矛盾 | 保留 + 补充 | 补**物品唯一持有**（靠单值槽位唯一索引，不靠检查代码）、**称谓/视角一致** |
| R19 | 每轮后自动更新状态卡 | **修改** | 改为"每拍写事件 + 每场景关账"：每拍全量重写状态卡会让状态随生成随机漂移，且无法审计 |
| R20 | 设定锁：某些事实不可改 | 保留 | 补：锁必须防**换 ID 绕过**——新 ID 写同一 (实体,谓词,有效区间) 也要被拦，靠槽位唯一索引 + 锁表联动 |

| ID | 需求 | 判定 | 说明与失效机制 |
|---|---|---|---|
| R21 | 规划 Agent：大纲/卷纲/章纲/场景分块/事件分块/角色设定 | 保留 | 产出必须是**结构化提案**，用户勾选采纳才落库，不允许直接改设定 |
| R22 | 写作 Agent：把剧情记录写成章节文件 | 保留 | 补：写作 Agent **不发明事实**，只能重述已提交的 beat 与旁白 |

| R24 | 审批 Agent：核对世界观/设定，具备检索能力 | **修改** | 检索必须**只读 + 限定 scope + 不得写入**。审批的产物是 `issue` 列表，不是改稿 |
| R25 | 审批→修订 可直连 | **修改** | 默认关闭。开启后是两个独立权限（转发问题 / 应用修订），且**去重 + 限 3 轮 + 必须留作者接管出口**。否则两个 Agent 会互相"修好"到面目全非 |

### 1.5 回退与版本

| ID | 需求 | 判定 | 说明与失效机制 |
|---|---|---|---|
| R26 | 用户↔Agent 对话可回退，内容一起回退 | **修改为检查点回退** | 见"最贵的错误 #3"。回退必须列全 8 个状态域（消息/事实/认知/关系/正文/卡牌/摘要/向量），少退一个不会报错，只会让下一轮读到已撤销的状态 |
| R27 | Agent↔Agent 对话也可回退 | **修改** | 回退不是删行，是**开新分支**。旧分支必须仍可读，否则"实验一下"变成不可逆操作 |
| R28 | 内置 MinGit，支持提交/Diff/历史/回退 | **修改** | MinGit 只管**章节文件**。角色记忆不在 Markdown 里，`git checkout` 恢复不了。必须"Git 提交 ↔ 业务检查点"双向绑定，见 `01-architecture.md §7` |

### 1.6 原方案缺失、但必须补的（这一档最贵）

| ID | 补充项 | 为什么必须有 | 缺了会怎样 |
|---|---|---|---|
| S1 | **断言 vs 事实分离** | 角色说的话是 `claim`，世界真相是 `fact`。二者不能合并 | 角色一撒谎，世界状态就被污染；后面所有推理都建立在谎言上 |
| S2 | **感知 = 消息级受众集合** | "同场"只是可感知的必要条件，不是充分条件 | 耳语、心理独白、读者向旁白被广播给全场 |
| S3 | **幂等收据 + expected_head** | 重试、双击、网络超时都会重放命令 | 同一拍被写两次，人物说了两遍同样的话 |
| S4 | **outbox + 内容哈希** | SQLite 与 Markdown 是两套真相 | 用户在编辑器里改了文件，数据库不知道；下次发布覆盖用户改动 |
| S5 | **分支模型** | 回退、试验、分支剧情都要能共存 | 只有一条时间线时，回退=销毁，用户不敢点 |
| S6 | **节拍（beat）实体与调度审计** | 要能回答"这一拍为什么是它说话" | 调参全靠感觉，出问题无法归因 |
| S7 | **token 预算与降级阶梯** | 上下文一定超预算 | 静默截断 → 模型凭空编；或者请求直接 400 |
| S8 | **模型 provider 抽象 + 成本护栏** | 一个项目会混用便宜模型（调度/摘要）和贵模型（正文） | 单模型跑全程，成本高 3–5 倍且质量不升 |
| S9 | **schema_version 与迁移** | 桌面应用会用到第二年 | 升级即毁库 |
| S10 | **中文输入法下的 Enter 语义** | IME 组合态按 Enter 是"选词"不是"发送" | 用户每打一个词就发一条消息，这是中文桌面应用第一大 bug 来源 |

## 2. 三个最贵的错误

只挑三条，因为人只记得住三条。每条一个数字。

### #1 把发言权交给模型

自由抢话（无阻尼、无节奏）在 500 拍合成序列上：**最长连任 12–15 拍，单人占比 52–58%，旁白占比 0%**。
加评分 + 阻尼 + 硬上限后：**最长连任 3 拍，单人占比 ≤38.5%，旁白 16.8%**。

三个后果叠加：读者看到的是一场独角戏；每拍多一次模型调用（每场 +40 次、+50,400 tok）；回退后无法复演同一场（模型每次选的人可能不同）。

### #2 把上下文全量喂进去，再用提示词要求"别知道"

12 场景 × 6 角色 = 72 次装配，204 条事实。全量注入时**每次装配平均 128.7 条越权事实**——角色不知道哪些是自己不该知道的，它只知道"这些都在我的上下文里"。
前置过滤后**累计越权 0 条**，同时事实块 token 从 1836 降到 678。

提示词里的"禁止全知"不是权限隔离。未授权内容一旦进入模型，你就只能祈祷。

### #3 回退只回退消息

一场戏的状态分布在 **8 个域**：消息、事实、认知（谁知道什么）、关系、正文、事件卡、摘要、向量。
只删消息 = 退了 1/8。表现是：对话回到三拍前，但角色仍然记得三拍前才揭晓的秘密，下一拍直接说漏。**不报错，只是逻辑崩了**，而且用户会以为是模型笨。

正确做法是检查点 + 全量重放（实测 200 事件重放 **0.45 ms**，成本可忽略，没有理由只退一半）。

## 3. 如果只做三件事

1. **知识边界做成表，不做成提示词。** `cognition` 表 + 前置过滤。这一条决定产品是不是"能写长篇"，其它都是体验。
2. **发言权与收束做成代码，不做成模型。** 评分 + 阻尼 + 硬上限 + 机器可判定的退出条件。这一条决定它是不是"能自己跑下去"。
3. **回退做成检查点分支，不做成删除。** 8 域全量 + 开新分支。这一条决定用户敢不敢让它跑。

其余功能（六类 Agent、Git、TUI/GUI、导出）都是在这三条上长出来的。这三条做错，后面每加一个功能都更贵。

## 4. 明确不做（本期边界）

- **不做多人协作 / 云同步**。桌面单机 + 本地文件夹，同步交给用户自己的网盘（并接受冲突风险，见 `05-roadmap.md` 风险表）。
- **不做模型微调**。只做提示词 + 检索 + 结构化输出。
- **不做自动插图 / 语音**。P5 之后再评估。
- **不做在线发布**。导出 Markdown / EPUB 即可。
- **不做插件市场**。skill 目录先做成普通文件夹 + 清单文件。

## 5. 术语（后文统一）

| 术语 | 含义 |
|---|---|
| 项目 / project | 一个小说工程，绑定一个文件夹 |
| 分支 / branch | 一条时间线。回退 = 开新分支，不删除旧分支 |
| 检查点 / checkpoint | 可回退的最小单位，绑定一个事件 seq |
| 场景 / scene | 一次连续的时空单元，有目标、在场者、结束条件 |
| 拍 / beat | 一次发言权分配 + 一次生成。场景由若干拍组成 |
| 受众 / audience | 一条消息被哪些角色感知。**不是**在场者列表 |
| 认知 / cognition | "某角色知道某事实"的记录。没有行 = 不知道 |
| 事实 / fact | 世界客观状态，三态（真/未知/假），可 supersede 不可覆盖 |
| 断言 / claim | 角色在台词里声称的内容。可能是谎言，不等于事实 |
| 导演 / director | 代码模块，负责发牌、升级冲突、叫停、记事件。不是 LLM |
