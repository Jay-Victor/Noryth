> 阶段 23 / 24（M2 第 5 阶段）｜ 依赖：19–22 ｜ 下游：24

## 1 本阶段要证明什么

| # | 假设 | 验证方式 |
|---|---|---|
| 1 | 10 万字项目打开仍 <800ms | `PERF-M2-01` 预热后 20 次取 P50/P95 |

| 4 | 成本报表、声音指标、归档候选查询有界 | 单次查询 P95 上限；查询计数无 N+1 |

## 2 范围

### 2.1 做

- M2-6：`PERF-M2-01` 夹具：3 卷 × 10 章、10 万字、5 角色、约 3k 条记忆、30 份章末摘要、覆盖 30 章各场的声音指标、完整成本行、12 条伏笔。
- M2-6：测量打开、切章、T23 时间线、检索、上下文装配、成本报表、声音指标、归档候选、Markdown/DOCX 导出、RSS。
- M2-6：只按测量结果加索引/批查询/虚拟列表；必要时迁移 `0015` 只允许加索引，不加表。
- 基线 `docs/M2-PERF-BASELINE.md`：夹具、机器、命令、P50/P95、查询计数、RSS、局限。
- 回归：`PERF-01` / `PERF-M1-01` 与 M1 E2E 不得退化。

### 2.2 不做

- 不换数据库、不引入第二个连接、不做独立向量库、不做 SQLite 分片。
- 不做 100 万字 / 多项目并行 / 多窗口性能；M2 目标是 10 万字单项目。
- 不为跑分压缩夹具文本；每拍文本必须唯一且可读，避免压缩率作弊。
- 不做 UI 视觉改版；只做列表虚拟化、分页、查询下推。
- 不把性能门放进每次提交；墙钟断言只在 nightly / 发布前跑。

## 5 实现要点

### 5.1 夹具（确定性、唯一文本）

- 3 卷 × 10 章，每章 3 场 × 8 拍，24 拍/章；每拍文本按 `章-场-拍-角色` 唯一前缀生成，避免全篇同文导致压缩率/缓存命中虚高。
- 总字数 ≥100,000（中文字符，去空白）；5 角色，声线夹具要能产生有区分度的指标（不能全是同一句）。
- 数据状态：30 章全部有 revision（final 或 current），30 份摘要，覆盖 30 章 × 3 场的 `voice_metric`，约 3,000 条 `memory_entry`（active，含少量 archived），3,000 条 `memory_vec` / `memory_fts`，成本行覆盖 planner/orchestrator/character/narrator/reviewer/memory，12 条伏笔（8 closed / 4 open）。向量用固定确定性 512 维值直接写入，perf 不启动 ONNX；声音指标可用纯函数生成或固定 JSON 种子。
- 生成脚本必须幂等：同一 seed 两次生成逐字节一致；不依赖随机数。
- 夹具不提交大文件；`tests/perf` 在临时目录生成，跑完清理。

### 5.2 目标

| 场景 | 目标 | 口径 |
|---|---|---|
| 打开 100k 项目 | <800ms | 含迁移检查、verify、最近章摘要；不含模型 |
| 切章 | P95 <120ms | 点击到正文可读；不读全书 |
| T23 时间线 | P95 <100ms | 30 章 / 24 拍 |
| 检索 | P95 <80ms | 3k 记忆，top_k 8；vec + FTS + RRF |
| 上下文装配 | P95 <150ms | 24 拍 / 5 角色 / L0–L3 |
| 成本报表 | P95 <200ms | 30 章 + 6 Agent + 项目级 |
| 声音指标 | P95 <100ms | 单场 24 拍，含持久化读取 |
| 归档候选 | P95 <200ms | 3k 条，50 条上限 |
| 导出 Markdown | <2s | 100k 字 |
| 导出 DOCX | <5s | 100k 字，含目录 |
| RSS | <600MB | Electron 全部进程私有工作集合计 |

- 打开/切章/检索/装配/报表均预热 3 次、采样 20 次；P95 用最近秩；记录机器 CPU/磁盘/Windows 版本。
- 查询计数：用测试 runner 包装 `prepare/execute`，断言报表/声音/归档路径的查询数不随章数线性增长（无 N+1）。
- 性能门只在 `pnpm test:perf` / nightly；提交门只跑功能 E2E。

### 5.3 优化顺序

1. **先测量，后加索引**：对慢查询跑 `EXPLAIN QUERY PLAN`，只加确实被使用的索引。
2. **报表下推**：成本按 `(project_id, chapter_id)` 与 `(project_id, agent_key)` 聚合；字数按 revision 清单一次算，不逐章读正文。
3. **声音指标**：按 `(scene_id, revision_id)` 命中缓存；没有则纯函数计算，不重复读拍。
4. **归档候选**：先按 `kind/status/importance/archived_at` 过滤，再做相似度；相似度只对同角色小集合算，不扫全库。
5. **UI**：成本报表 >100 行用 `VirtualList`；记忆归档列表分页 50；章节列表沿用 M1 的摘要查询，不加载正文。
6. **迁移 0015**：仅当上述仍不达标；只允许 `CREATE INDEX`，不加表/列；若未使用，`LATEST_SCHEMA_VERSION` 保持 14，阶段文档记录「未新增」。

### 5.4 回归

- `pnpm test:perf` 同时跑 `PERF-01`（30 章 / 14.8 万字 / 切章/检索/导出）与 `PERF-M2-01`；旧数字不得退化 >10%（同机同夹具）。
- `E2E-M1-SMOKE`、`E2E-M1-A`（nightly）、`E2E-M2-ARCHIVE-01`、`COST-M2-02` 全绿。
- 若优化改变了查询语义（例如报表字数口径），先写测试再改；不以性能为由放宽断言。
- 100k 夹具不进入每个提交；`pnpm test:perf` 在 nightly 与发布前跑，记录实际数字。

## 7 风险与回退

| 风险 | 触发 | 回退 |
|---|---|---|
| 100k 夹具生成慢 | CI 超时 | 生成脚本缓存/seed 复用；只在 nightly 跑 |
| runner 抖动 | P95 偶发超标 | 性能不进提交门；记录同机对比与三次中位数 |
| 索引拖慢写入 | 每拍写入变慢 | 只加读路径必要索引；写入基准一并测；不行就撤索引 |
| 报表 N+1 | 30 章查询爆炸 | 先聚合再取标题；查询计数断言；分页 |
| 压缩率作弊 | 全篇同文让 DOCX/缓存虚高 | 每拍唯一文本；断言可见正文 >100k 字 |
| 优化伤功能 | 省 token/查询改语义 | 功能 E2E + 契约测试先行；性能优化单独提交，可回退 |
